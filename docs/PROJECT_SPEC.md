## 1. Анализ входных данных

### 1.1 Брендбук Contrast

Брендбук описывает офлайн-айдентику: монограмма + вордмарк CONTRAST, палитра чёрный + золото/бронза градиентом, шрифт с широким трекингом. Применяется сплошь: визитки, бланки, сертификаты, пакеты, стаканы, мундштуки, футболки, кепки, вывеска, брендирование транспорта — везде тёмный фон + золото как основной, а не акцентный цвет.

**Важно:** это система для физических носителей, где «дорогой клуб» считывается мгновенно. Для сайта такой подход в чистом виде не годится — это прямо противоречит тому, что ответила Алуа в брифе (см. 1.3).

### 1.2 Заполненный бриф — ключевые ответы заказчика

| Вопрос | Ответ Алуа |
|---|---|
| ЦА | 27+, есть опт для лаунж-заведений; в основном покупают для себя, иногда подарочные боксы |
| Направление | НЕ вариант А в чистом виде. А + элементы B. Без чрезмерно тёмного фона, без золота/меди как доминирующего |
| Обязательный функционал | Удобный каталог, категории, поиск, фильтры, понятные карточки товара, цена, характеристики, **остаток товара** |
| Фото товаров | Готовые фото с официальных сайтов поставщиков (не свои) |
| Первый экран | Приоритет: 1) кнопка WhatsApp → 2) баннер/акции → далее поиск/категории |
| Референс | aesop.com — сочетание эстетики и удобства |

Отдельно и явно прописано: **не делать весь сайт тёмным**. Тёмный/атмосферный — только первый экран/блок, дальше — спокойный нейтральный фон. Премиальность — через типографику, фото, пространство и аккуратные акценты, не через тёмные заливки. В приоритете читабельность и понятная подача товара.

### 1.3 Главный вывод — конфликт брендбука и брифа, и как его закрыть

Это ключевое дизайн-решение проекта, и его стоит зафиксировать с Алуа **до** старта макета, иначе есть риск, что первый макет не зайдёт:

- Брендбук = золото/чёрный как система по умолчанию.
- Бриф = золото/чёрный как **акцент**, не система.

Практический вывод для макета: тёмный + золото живут только в hero-блоке первого экрана (там, где сейчас логотип и настроение), дальше — светлый/нейтральный фон в духе Aesop, монограмма и золото используются точечно (иконки, кнопки, разделители, hover-состояния), а не как заливка блоков каталога. Это стоит явно проговорить с Алуа одной фразой перед сдачей макета, чтобы не тратить правки на то, что уже решено в брифе.

### 1.4 CRM: определена — Poster POS, сетевая структура

Присланные ссылки — это **Poster POS** (joinposter.com), облачная POS/CRM-система для розницы и HoReCa с открытым API (dev.joinposter.com), популярная в РК/СНГ.

По структуре из 4 адресов:

- `connect-contrast-centre` — по терминологии Poster это, вероятно, **Connect-аккаунт**: центральный аккаунт сети/франшизы, где ведётся общий каталог/меню, синхронизируемый в аккаунты точек.
- `contrast-left`, `contrast-al-farabi`, `contrast-centre` — вероятно отдельные аккаунты **точек продаж**, у каждого свой склад/остатки.
- `.../manage` — вход в админ-панель конкретного аккаунта.

Это не подтверждено — предположение на основе публичной архитектуры Poster для сетей/франшиз, требует проверки при аудите (см. раздел 3). Но если это так, есть два практических следствия:

1. **Хорошая новость:** каталог товаров, скорее всего, единый (ведётся в Connect-аккаунте) → карточки товара, атрибуты, категории не придётся дублировать на 4 разных источника.
2. **Момент, который нужно проверить отдельно:** остатки и, вероятно, программа лояльности/бонусы могут быть **разделены по точкам**, а не общими на сеть. Если бонусы не объединены — «кэшбэк в личном кабинете по номеру телефона» (Этап 2) не будет работать корректно для клиента, который покупал в разных точках, пока это не решено на уровне CRM. Это прямо влияет на оценку Этапа 2.

## 2. Финальное ТЗ

### 2.1 Принципы дизайна (зафиксировать с Алуа перед стартом макета)

- Первый экран: тёмный/атмосферный, с монограммой и золотым акцентом — «витрина» бренда.
- Далее по сайту: светлый, нейтральный фон, премиальность через типографику/фото/пространство.
- Обязательные элементы первого экрана по приоритету: WhatsApp-кнопка → баннер/акции → поиск/топ-категории.
- Каталог: категории, поиск, фильтры, карточки с ценой, характеристиками и остатком.
- Стиль подачи товара — по референсу Aesop: чисто, много воздуха, крупные фото, минимум декоративных элементов.

### 2.2 Экраны макета (Этап 1, 3-5 раб. дней)

1. Главная — hero (см. 2.1), баннер/акции, топ-категории.
2. Каталог — сетка товаров, фильтры, поиск.
3. Карточка товара — фото, цена, характеристики, остаток, CTA.

### 2.3 Функционал Этапа 1 (720 000 ₸, зафиксировано в КП)

- Сайт с нуля на новом дизайне.
- Интеграция с CRM (Poster): каталог, карточки товаров, складские остатки по филиалам с автоскрытием товаров не в наличии.
- Интеграция с Яндекс Доставкой.
- SEO-подготовка: URL, мета-теги, скорость, sitemap.
- Перенос сайта на домен заказчика *(домен пока не назван — нужно уточнить у Алуа, см. раздел 7)*.

### 2.4 Функционал Этапа 2 (предварительно, требует аудита CRM)

- Фильтры каталога: бренд, цена, крепость, вкус, фасовка.
- Личный кабинет: история заказов + отображение кэшбэка по номеру телефона.
- Форма согласия на обработку персональных данных (закон РК «О персональных данных»).

### 2.5 Функционал Этапа 3 (предварительно, требует уточнения логики)

- Кросс-сейл: доп. товары/рекомендации в карточке заказа. Логика подбора (по категории / по бренду / вручную заданные связки) не определена — влияет на стоимость.

### 2.6 Стек (подтверждён)

Next.js на Vercel, GitHub, `.env` для ключей Poster API и Yandex Delivery, Claude Code — основная среда разработки.

## 3. Чек-лист аудита CRM (нужно закрыть до оценки Этапа 2–3)

Это список того, что нужно физически посмотреть в 4 аккаунтах Poster:

1. В каком аккаунте реально ведётся каталог товаров и категории — в Connect или в каждой точке отдельно?
2. У товаров есть структурированные атрибуты (бренд, крепость, вкус, фасовка) отдельными полями — или всё текстом в названии/описании?
3. Как устроены остатки: отдельный склад на каждую точку, общий склад, или смешанно?
4. Подключена ли программа лояльности/бонусы в Poster, и **общая ли она на все 4 точки** или считается отдельно по каждой?
5. Как формируется кэшбэк — процент от суммы, фиксированный, начисляется вручную?
6. Есть ли доступ через API к истории чеков/заказов по номеру телефона клиента?
7. Сколько всего активных SKU и категорий — нужно для оценки объёма работы по фильтрам.
8. Как сейчас реально принимаются заказы — вручную через WhatsApp или через Poster?
9. Открыт ли API-доступ на тарифе всех 4 аккаунтов, или для API нужен апгрейд тарифа?

## 8. Когда перейдёшь в Claude Code

Рекомендуемая структура на старте:

```
hookah-market/
├── docs/
│   └── PROJECT_SPEC.md      ← этот документ, вставь как есть
├── app/                      ← Next.js
├── .env.example               ← POSTER_API_TOKEN_LEFT, POSTER_API_TOKEN_CENTRE, POSTER_API_TOKEN_ALFARABI, POSTER_CONNECT_TOKEN, YANDEX_DELIVERY_TOKEN
└── README.md
```

Положи этот файл в `docs/` первым — Claude Code сразу получит весь контекст проекта (бриф, ТЗ, структуру CRM, бэклог) без необходимости объяснять всё заново.
