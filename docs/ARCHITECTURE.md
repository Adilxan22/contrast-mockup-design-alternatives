# Архитектура интеграции с Poster — технические заметки

Внутренний документ (не для клиента). Фиксирует решения, принятые по итогам аудита ([Poster_CRM_Audit_Report.pdf](Poster_CRM_Audit_Report.pdf)) и разбора API-документации Poster (github.com/joinposter/docs).

## 1. Приём заказа (Этап 1, без личного кабинета)

Гость собирает корзину → сайт вызывает `incomingOrders.createIncomingOrder` на аккаунте нужного филиала (`spot_id`), передаёт `phone` (без `client_id` — Poster сам найдёт/создаст клиента по номеру). Заказ сразу появляется в кассе филиала.

Не требует логина/аккаунта — гостевой чекаут работает уже на телефоне без сессии. По сложности сопоставимо с прежним планом "заказ через WhatsApp", отдельно не тарифицируется, входит в существующую стоимость Этапа 1 (720 000 ₸).

Параллельно — уведомление менеджеру в WhatsApp/Telegram о новом заказе (простой серверный вызов после успешного `createIncomingOrder`).

## 2. Синхронизация статуса и кэшбэк (Этап 2, привязано к личному кабинету)

Подтверждено: Poster поддерживает вебхуки на события `transaction` (закрытие чека) и `incoming_order` (смена статуса нового/принятого/отклонённого заказа). Ограничений по тарифу нет. Подписка настраивается в настройках приложения разработчика (`web/webhooks.md`).

Схема: закрытие чека менеджером → вебхук `transaction` → сайт помечает заказ «Исполнено» и подтягивает актуальный баланс бонусов клиента (`clients.getClient` → поле `bonus`, в копейках). Если вебхуки по какой-то причине не долетают — запасной вариант поллинга через `transactions.getTransactions`.

## 3. Личный кабинет — вход по телефону, без пароля

Идентификатор — номер телефона, тот же, что использует Poster. Метод `clients.getClients` принимает фильтр `phone` (международный формат) — можно найти/связать клиента сайта с клиентом Poster напрямую по номеру, без отдельной "склейки" email/телефона.

Вход: телефон → одноразовый код (SMS или WhatsApp OTP через внешнего провайдера — добавится в `.env`) → сессия. Email не используется как логин.

## 4. Каталог и атрибуты (Этап 2, фильтры)

Подтверждено аудитом: атрибуты (бренд/вкус/крепость/фасовка) не структурированы, всё текстом в названии товара. План: разовая синхронизация каталога → парсер на словарях известных брендов/вкусов + регулярки на крепость/фасовку → собственная БД со структурированными полями → админка для ручной доразметки того, что не распозналось (ожидаемо 5-15% SKU).

## 5. Итог по разделению стоимости

- Гостевой чекаут через API (без ЛК) — в рамках Этапа 1, доплаты не требует.
- Вебхуки, синхронизация статуса, отображение кэшбэка, вход по OTP — Этап 2, "Личный кабинет".
- Парсинг атрибутов и UI фильтров — Этап 2, "Фильтры каталога".
